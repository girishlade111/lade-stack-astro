## はじめに

インスタンスサイズの適正化（Rightsizing）、リザーブド／Savings Plans によるコミットメント割引、ストレージライフサイクル管理、そして厳格なタグ付け規律：スタートアップのクラウド請求額を 30〜50 % 削減するための実践的プレイブックです。本ガイドでは、基本概念からトレードオフ、今週から現場へ導入できる本番仕様のワークフローまでを詳しく解説します。

## なぜ重要なのか

- **開発者ベロシティの向上**: コスト監視を自動化することで、月末の煩雑な明細チェックや経費精算の手間を排除します。
- **システムの信頼性向上**: 稼働メトリクスに基づく適正化を行うことで、安易なリソース削減による本番障害を防ぎます。
- **コストコントロール**: 予測不能なクラウド請求の急増をなくし、ランウェイ（資金維持期間）を大幅に延伸します。

## コアコンセプト

### 1. 最小の実装スライスから着手する

全社的な FinOps 体制を一度に立ち上げる前に、まずはエンドツーエンドで動作する単一のバーティカルスライスを完成させます。**スタートアップのクラウド節約術**においては、請求額の最も大きい上位 1 つのコンポーネント（例: 本番 DB インスタンス）にタグを付与し、日次でのコスト可観測性を確立することを意味します。

### 2. 「成功の落とし穴」を広く設ける

個人の裁量に頼るのではなく、開発・ステージング環境を夜間に自動停止するスクリプトを導入し、自然とコストが抑制される仕組みを作ります。本番対応の最小スターター構成例：

```typescript
// Minimal production-ready starter
export const config = {
  retries: 3,
  timeoutMs: 5_000,
  circuitBreaker: { failures: 5, cooldownMs: 30_000 },
};

export async function runWithResilience<T>(fn: () => Promise<T>): Promise<T> {
  let lastError: unknown;
  for (let attempt = 1; attempt <= config.retries; attempt++) {
    try {
      return await fn();
    } catch (err) {
      lastError = err;
      await new Promise((r) => setTimeout(r, attempt * 250));
    }
  }
  throw lastError;
}
```

### 3. 真に重要な指標を計測する

| 指標 | 推奨される初期ターゲット |
| --- | --- |
| p95 レイテンシ | < 300 ms |
| エラーバジェット消費率 | < 2% / 30 日 |
| デプロイ頻度 | 毎日 (Daily) |
| ロールバック所要時間 | < 10 分 |

## 本番チェックリスト

1. 環境タグとチームタグを付与したクラウドアカウントのコスト構造化データを導入する。
2. データ転送量（Egress）の急増を検知して通知する機能フラグ（Feature Flag）を設定する。
3. リリース前に不要になったテスト用スナップショットや未アタッチの EBS ボリュームを棚卸しする。
4. 発生頻度の高い上位 3 つのコストインシデント（NAT ゲートウェイの異常通信、ログの無期限保持、ゾンビインスタンス）に対する運用手順書（Runbook）を整備する。

## よくある落とし穴

> 実際のユーザーが付く前にプラットフォームを過剰に作り込まないこと。早期に選んだ技巧的な技術よりも、適切に選ばれた堅実な技術のほうが遥かに成果を生みます。

- アーキテクチャが固まる前に 3 年間のリザーブドインスタンスを購入し、後から変更不能になること。
- S3 などのオブジェクトストレージで古いバージョンの削除ライフサイクルを設定せず、課金が累積すること。
- 深夜の緊急呼び出しにつながる予算超過アラートの未設定。

## まとめ

**スタートアップのクラウド節約術**は、小さく観測可能なステップで反復を重ねるチームに大きな成果をもたらします。上記のチェックリストを起点に、週に 1 つの課題を自動化し、エンジニアリングの成功を積み重ねていきましょう。
