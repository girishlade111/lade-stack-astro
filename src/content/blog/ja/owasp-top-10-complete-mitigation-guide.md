## はじめに

OWASP Top 10 が警告する 10 大セキュリティリスクを徹底解説：脆弱性を含むコードと修正後の堅牢なコードを並べて対比し、現場の開発者が今日から直ちに適用できる具体的な防御策を提示します。本ガイドでは、基本概念からトレードオフ、今週から現場へ導入できる本番仕様のワークフローまでを詳しく解説します。

## なぜ重要なのか

- **開発者ベロシティの向上**: CI パイプラインでの静的セキュリティテスト（SAST）により、手戻りの大きい手動修正を未然に防ぎます。
- **システムの信頼性向上**: 多層防御（Defense in Depth）を構築し、1 つの脆弱性が直ちに大規模なデータ漏洩につながる事態を回避します。
- **コストコントロール**: セキュリティ事故発生時の調査費用、事業停止損害、制裁金リスクを大幅に圧縮します。

## コアコンセプト

### 1. 最小の実装スライスから着手する

全社的なセキュリティ診断を待つ前に、まずはエンドツーエンドで動作する単一のバーティカルスライスを完成させます。**OWASP Top 10完全対策ガイド**においては、認証・認可エンドポイントおよび入力フォームのバリデーションを固め、初日からアクセス監視を確立することを意味します。

### 2. 「成功の落とし穴」を広く設ける

個別のコードで手動のエスケープ処理を書くのではなく、ORM によるパラメータ化クエリや、テンプレートエンジンの自動エスケープをデフォルト化します。本番対応の最小スターター構成例：

```typescript
// Minimal production-ready starter
export const config = {
  retries: 3,
  timeoutMs: 5_000,
  circuitBreaker: { failures: 5, cooldownMs: 30_000 },
};

export async function runWithResilience<T>(fn: () => Promise<T>): Promise<T> {
  let lastError: unknown;
  for (let attempt = 1; attempt <= config.retries; attempt++) {
    try {
      return await fn();
    } catch (err) {
      lastError = err;
      await new Promise((r) => setTimeout(r, attempt * 250));
    }
  }
  throw lastError;
}
```

### 3. 真に重要な指標を計測する

| 指標 | 推奨される初期ターゲット |
| --- | --- |
| p95 レイテンシ | < 300 ms |
| エラーバジェット消費率 | < 2% / 30 日 |
| デプロイ頻度 | 毎日 (Daily) |
| ロールバック所要時間 | < 10 分 |

## 本番チェックリスト

1. 認証失敗や不正入力試行を記録する構造化セキュリティログを導入する。
2. 攻撃を受けたエンドポイントを即時遮断できる WAF ポリシー用の機能フラグを設定する。
3. リリース前に依存ライブラリの脆弱性スキャン（npm audit 等）を自動実行する。
4. 発生頻度の高い上位 3 つの侵害シナリオ（クレデンシャルスタッフィング、SQL インジェクション試行、IDOR 悪用）に対する運用手順書（Runbook）を整備する。

## よくある落とし穴

> 実際のユーザーが付く前にプラットフォームを過剰に作り込まないこと。早期に選んだ技巧的な技術よりも、適切に選ばれた堅実な技術のほうが遥かに成果を生みます。

- クライアント側（ブラウザ側）のバリデーションだけで安心し、サーバー側の検証を省略すること。
- 他ユーザーの ID を URL やボディに指定することで他人の情報が閲覧できてしまう認可制御漏れ（IDOR）。
- 深夜の緊急呼び出しにつながるブルートフォース攻撃検知アラートの未設定。

## まとめ

**OWASP Top 10完全対策ガイド**は、小さく観測可能なステップで反復を重ねるチームに大きな成果をもたらします。上記のチェックリストを起点に、週に 1 つの課題を自動化し、エンジニアリングの成功を積み重ねていきましょう。
