## はじめに

「決して信頼せず、常に検証せよ」：社内ネットワーク境界の信頼を前提とせず、ID 認識プロキシ（IAP）、短期資格情報（一時トークン）、マイクロセグメンテーションを通じてウェブアプリケーションのゼロトラストセキュリティを確立します。本ガイドでは、基本概念からトレードオフ、今週から現場へ導入できる本番仕様のワークフローまでを詳しく解説します。

## なぜ重要なのか

- **開発者ベロシティの向上**: 煩雑な VPN 接続や手動の秘密鍵共有を撤廃し、安全でスムーズな開発環境を実現します。
- **システムの信頼性向上**: 内部の 1 つのノードが侵害されても、横展開（ラテラルムーブメント）を確実に封じ込めます。
- **コストコントロール**: セキュリティ侵害インシデントへの緊急対処費用や、レガシーな専用ハードウェア機器の維持費を削減します。

## コアコンセプト

### 1. 最小の実装スライスから着手する

全社的なゼロトラスト基盤を一挙に敷設する前に、まずはエンドツーエンドで動作する単一のバーティカルスライスを完成させます。**ウェブアプリのゼロトラスト**においては、内部管理画面へのアクセスを ID 認識プロキシ経由に切り替え、初日からのアクセス可観測性を確保することを意味します。

### 2. 「成功の落とし穴」を広く設ける

開発者個人に複雑な暗号設定を委ねるのではなく、標準的な mTLS や SSO ミドルウェアを組み込み、自然と安全な通信が行われるようにします。本番対応の最小スターター構成例：

```typescript
// Minimal production-ready starter
export const config = {
  retries: 3,
  timeoutMs: 5_000,
  circuitBreaker: { failures: 5, cooldownMs: 30_000 },
};

export async function runWithResilience<T>(fn: () => Promise<T>): Promise<T> {
  let lastError: unknown;
  for (let attempt = 1; attempt <= config.retries; attempt++) {
    try {
      return await fn();
    } catch (err) {
      lastError = err;
      await new Promise((r) => setTimeout(r, attempt * 250));
    }
  }
  throw lastError;
}
```

### 3. 真に重要な指標を計測する

| 指標 | 推奨される初期ターゲット |
| --- | --- |
| p95 レイテンシ | < 300 ms |
| エラーバジェット消費率 | < 2% / 30 日 |
| デプロイ頻度 | 毎日 (Daily) |
| ロールバック所要時間 | < 10 分 |

## 本番チェックリスト

1. ユーザー ID、デバイス状態、リクエストコンテキストを含む構造化アクセスログを導入する。
2. 異常なアクセス元からの通信を即時遮断できるポリシーフラグ（Feature Flag）を整備する。
3. リリース前に暗号化プロトコルネゴシエーションに伴うハンドシェイク遅延を検証する。
4. 発生頻度の高い上位 3 つのセキュリティシナリオ（トークン漏洩、IdP 障害時のアクセス制限、特権昇格試行）に対する運用手順書（Runbook）を整備する。

## よくある落とし穴

> 実際のユーザーが付く前にプラットフォームを過剰に作り込まないこと。早期に選んだ技巧的な技術よりも、適切に選ばれた堅実な技術のほうが遥かに成果を生みます。

- 有効期限の長い固定 API キーをサービス間通信に使い続けること。
- クラスタ内部の通信を暗黙的に安全と見なし、平文 HTTP で通信させること。
- 深夜の緊急呼び出しにつながる認証失敗急増アラートの未設定。

## まとめ

**ウェブアプリのゼロトラスト**は、小さく観測可能なステップで反復を重ねるチームに大きな成果をもたらします。上記のチェックリストを起点に、週に 1 つの課題を自動化し、エンジニアリングの成功を積み重ねていきましょう。
